# 這份 Wiki 是給誰看的

固定收益／債券交易部門的同仁，查詢跟業務相關的法規重點時使用。使用者不
是法律專業，頁面要用白話文解釋「這條法規規範什麼、跟我們的業務有什麼關
係」，不是逐條翻譯法條全文，也不是法律意見書。

# 每個法規頁面要包含什麼

寫進 `regulations/` 底下，檔名用來源檔名（去掉副檔名），例如來源是
`銀行法.pdf`，頁面就叫 `銀行法.md`。每頁固定包含以下段落：

1. **這是什麼**：一到兩句話說明這部法規規範的範圍
2. **跟我們業務的關聯**：具體點出哪些條文/規定會影響固定收益／債券交易
   部門的日常作業（額度限制、揭露義務、資本計提、交易對手適格性等），
   沒有明確關聯的條文不用硬寫
3. **關鍵定義**：法規裡容易搞混或常被問到的名詞解釋
4. **相關法規**：用 `[[法規名稱]]` 連結到其他相關頁面（不確定有沒有相
   關頁面存在也沒關係，先寫上名稱，之後那頁建立了連結自然就會生效）

# Frontmatter 格式

每頁最上面固定放這個格式（純量欄位，不要用巢狀結構，因為查詢工具只用簡
單的正規表示式解析，不是完整的 YAML parser）：

```yaml
---
type: Regulation
title: 法規全名
description: 一句話摘要（用於 index.md 的列表，不要超過一行）
tags: 用逗號分隔的關鍵字，例如 銀行,授信,資本適足率
source_file: 原始來源檔名
effective_date: YYYY-MM-DD（如果來源內容有提到生效日）
---
```

# 更新規則

同一份來源檔名重複匯入（例如法規修正後的新版 PDF，檔名一樣）時，**更新
既有頁面**、不要整頁重寫成完全不同的結構——保留舊頁面裡跟這次來源內容
無關、但仍然正確的部分，只更新有變化的地方。如果收到的舊頁面內容看起來
跟新來源差異很大，才整頁重寫。

說明文字、不要用 ```markdown 這類程式碼區塊包起來。
